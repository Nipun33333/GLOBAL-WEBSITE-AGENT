# Security and operational controls

- Secrets live in environment variables/GitHub Secrets, never in source. `.env`, private exports, OAuth files, local databases, artifacts and caches are ignored. CLI failures print exception types rather than provider/SQL exception bodies that might expose credentials.
- Public-web fetching accepts only HTTP(S), standard ports and globally routable DNS answers. The resolved address is pinned into the actual HTTP/TLS connection; hostname certificate verification and Host headers retain the original hostname. Every redirect is revalidated. Private, link-local, loopback and mixed DNS results are rejected. Robots restrictions and inaccessible robots files stop research. No CAPTCHA, login or access-protection bypass is implemented.
- A maximum one-megabyte response, bounded snippets, fixed Gemini output schemas, timeouts, retry bounds, cost reservations, request caps and global preview/send caps limit work. Quota failures stop the affected operation. No purchase or billing management exists.
- Retrieved websites and emails are data. Gemini has no tool access. Only source-backed quotations become business statements. AI selects a safe design schema; a reviewed renderer supplies HTML/CSS and the only executable script. Escaping, restricted links, CSP and no forms limit injection risks. Default previews have no external media licensing dependencies.
- PostgreSQL provides durable idempotency and a common session-level advisory lock. An explicit lock assertion precedes external writes, detecting lock loss after reconnection. Use direct/session-mode database connections only. State is committed before non-idempotent Gmail/deploy calls; uncertain results are reconciled, not blindly repeated.
- Defaults deny commercial sending in every jurisdiction. Legal-policy review, eligibility evidence and history/audience validation are required. Imported historical recipients and withdrawals are suppressed. SMTP delivery and external business replies are never inferred from model text.
- Gmail uses compose and readonly scopes, validates the mailbox identity, and uses stable MIME Message-IDs. No email address guessing, impersonation, spoofed sender alias, automatic mailbox deletion, or anti-spam evasion is provided.
- The database contains business contact data, evidence, message bodies and model cache entries. Restrict administrator access, encrypt provider storage/backups, define retention/deletion policies according to your jurisdiction/provider contracts, and isolate the runtime DB role. Do not expose the schema through a public client API.
- Dependencies and hashes are committed in `uv.lock`, CI uses frozen installation, and GitHub action revisions use commit SHAs. Dependabot proposes updates; dependency advisories are checked in CI. This does not replace independent security review.

If credentials leak, disable this repository's sending/automation variables, revoke the affected credentials with their provider, replace secrets, and inspect the durable ledger. Preserve suppression/history state. Never clear the database to fix a duplicate-send issue.

Report security concerns privately to the repository owner. Do not include real tokens, business email bodies, or database passwords in public issues.
